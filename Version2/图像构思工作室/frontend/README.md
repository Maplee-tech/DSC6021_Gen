# Better Prompt 前端

这是原“图像构思工作室”的展示层重设计。继续使用原来的 Python/Gradio 服务，无需 npm、前端构建或额外模型接口。

## 启动

在 VS Code 打开 `/Users/maplelee/Desktop/图像构思工作室`，终端运行：

```sh
.venv/bin/python app.py
```

打开终端打印的本地地址。已有服务运行时，先在它的终端按 Ctrl+C，再重新启动以加载最新 CSS/JS。开发预览目前使用 `http://127.0.0.1:7878`。推荐桌面浏览器宽度 1280px 以上；窄窗口会把三面书页改成上下排列。

## 页面与原操作的对应

1. **咖啡馆 / 构思**：左侧输入初始想法；右侧是现有 AI 解析返回的真实卡片。A/B/C 与 D 自填、自由补充、画幅、高级要求、保存与确认均保留。确认后展开提示词，明确点击生成 V0；生成成功才自动翻到机场。
2. **机场 / 优化**：左侧展示保留图片与历史。右侧保留逐项写优化点、保存、多选、本轮方案预览、确认生成、补充新要求和高级检查。生成修改版成功后翻到服装店。
3. **服装店 / 版本**：左侧两版对照；右侧保留实际 G/R 结果、版本采用/回退、满意度、导出、跨版本偏好组合，以及继续优化的所有操作。后续修改仍留在本场景。

底部提供目录、前后翻页、音效开关、预设视角与合上按钮。手动翻页只切换展示，不自动调用模型。Alt+左右方向键也可翻页。

## 文件

- `better_shell.html`：封面、页眉、目录与控制栏。
- `better_center.html`：中央场景与对话界面。
- `better_prompt.css`：纸质三栏书页、折叠卡片、响应式与翻页样式。
- `better_scene.js`：Three.js 封面、三个独立场景、六位完整几何人物、灯光/阴影、拾取与视角控制。
- `better_prompt.js`：页面导航、卡片/人物联动、历史预览、真实检查数量汇总。
- `vendor/three.min.js`：本地固定版本 Three.js 0.160.1。
- `vendor/THREE-LICENSE.txt`：第三方库 MIT 许可证。

Three.js 在 `ui.py` 中与场景代码合并加载，不依赖在线 CDN。场景、人物、材质和封面印刷均在本地生成，没有外部 GLB/纹理的在线加载依赖。

## 实现边界

- 人物采用完整成人比例的程序化纸艺人偶；每个场景各有两位独立人物与道具。它们具备完整身体几何、材质、实际遮挡和阴影，可点击互动；当前采用纸艺模型外观。
- 封面是实际 3D 硬壳、书脊、纸页边缘和缎带。内页切换使用平滑旋转、旧场景折起与新场景展开，未实现软体纸张物理仿真。
- 真实卡片数量由原 AI 解析决定，不截断现有 19 项为固定 15 项；折叠面板保留全部字段。需要时只在书页内部滚动。
- 对话联动引用当前卡片内容，不发起额外 AI 请求。人物的引导话术是前端固定提示，不冒充模型分析结果。
- 现有原图编辑、算法排序、G/R 比较、预算、持久化、API 配置均未修改。

## 动画与性能

封面开合 1.4 秒；翻页 1.05 秒；场景折叠/展开 0.95 秒；卡片展开 0.28 秒；标签反馈 0.35 秒。支持减少动态效果设置。设备像素比限制 1.75，空闲场景约以 30fps 目标节奏绘制，交互/翻页提高更新频率；隐藏标签页暂停绘制。实际帧率取决于设备。

## 看图后补充与边缘翻页

第2、3页顶部提供自由补充入口，保存后的文字会显示并保留到刷新之后。生成前显示当前参考版本；上一轮的优化说明可单独查看。新增内容会产生新需求版本，不与旧标准直接比较G/R。

按住左右书页的空白处：内容到顶后向上拖动超过85px并松开，进入上一页；到底后向下拖动进入下一页。中途不会翻页；输入、选项、按钮与中央3D区域不触发此手势。

## 2026-11-12：修改意见与统一判断口径

- 逐项意见与自由补充都先调用已配置的文字模型。AI 返回纠正图片、改变目标、混合意见或需要澄清；界面展示原值→新值，用户确认后才写入。歧义可选择“纠正图片 / 改变或增加要求”再分析。每次分析计入已有调用预算。
- 纠正图片：目标不变，用户确认的判断关联当前这一次图像评价。改变目标：生成新需求版本及检查清单，替换相关字段，保留旧版本历史；先调用视觉模型按新目标检查当前保留图，再制定计划。重检失败保留新目标，可手动重试，不能携带旧检查结果直接生成。
- U 和 G/R 共用 `effective_checks`：同一次评价的最新用户纠错优先，否则使用模型判断。纠错只对该图、该目标、该次评价有效，不跨新目标或重新评价继承。重新评价和用户纠错会使旧计划失效。
- U 仍是 `sum(w*e) - lambda*sum(w_risk) - mu*C`；e_user=1、e_ai=0.6 属于规则系数，并非模型校准后的成功率。G/R 仍分别统计 fail→pass 和 pass→fail 的权重；两图必须使用同一个需求版本和评价标准，不确定不计入 G/R。当前页面只显示当前目标下的可比结果。
- 原始视觉模型评价、用户纠错、有效判断、公式项与历史比较分别留存；导出的 history.json 可追溯。需求约束图没有额外增加评分公式。
- 验证：77 项自动检查；真实配置接口完成反馈分类和视觉重新检查（临时任务副本，未生成新图片）；界面另用隔离任务验证确认、加载与计划，不改正式任务。
